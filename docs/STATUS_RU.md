# VTok — реальный статус проекта

Последнее обновление: 2026-10-22.

## Что есть в репозитории

- Android Compose-приложение-оболочка VTok с настройками интерфейса.
- Экран выбора страны с поиском и сохранением выбранного ISO-кода.
- Экраны настроек, разработчиков, плагинов, бейджей и обновлений в текущей оболочке.
- GitHub Actions workflow для сборки и базовой проверки Android-приложения.
- Отдельный workflow `.github/workflows/verify-source-apk.yml` для загрузки публичного APK по HTTPS и проверки всех записей ZIP-архива с отчётом.

## Что НЕ готово

- Это пока **не полноценный мод TikTok** и не форк исходного кода TikTok.
- Выбор страны в оболочке сохраняет настройку локально, но сам по себе не меняет ответы Android TelephonyManager и не меняет регион аккаунта на серверах TikTok.
- Сетевой прокси/обход ограничений не интегрирован в запросы TikTok и не должен считаться рабочим.
- UI плагинов и бейджей не означает, что есть безопасный загрузчик плагинов или серверная выдача бейджей.
- OTA-экран пока не подтверждает, что умеет безопасно устанавливать обновление.
- APK TikTok 47.2.41, ранее загруженный в Releases, имеет тот же SHA-256, что и копия, у которой локальная проверка выявила повреждённые ZIP-записи. Не использовать её как проверенный исходник.

## Следующий безопасный маршрут

1. Найти новый, законно полученный APK с прямой HTTPS-ссылкой на скачивание.
2. Открыть **Actions → Verify TikTok source APK → Run workflow**, вставить URL и запустить проверку.
3. Скачать артефакт `source-apk-verification-report` и убедиться, что итог — `RESULT: PASS`.
4. Только после этого отдельно пробовать MargyT и фиксировать логи, версию, ABI и SHA-256 результата.
5. Не объявлять регион, обход, плагины, бейджи или OTA работающими до проверки в настоящем целевом APK.

## Важное ограничение

Проверка ZIP/CRC подтверждает читаемость архива, но не доказывает безопасность APK, подлинность подписи, совместимость MargyT или работоспособность TikTok после модификации.
